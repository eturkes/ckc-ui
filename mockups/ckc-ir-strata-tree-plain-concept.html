What the spec actually commits

V1-V2 picking is deterministic. Model-based extraction is a separate V3 experiment.

SPEC.md §§4.5, 5, 8.3, 10, 12
V1-V2 path

Not an LLM picker

The layered pipeline is `runtime_ai: false`. Picked spans come from deterministic artifacts.

  • extractreal HTML parser creates SourceGraph nodes, spans, anchors, and regions
  • segmentrule-based segmentation keyed on fixture structure and sentence markers
  • normalizelexicon-driven mention binding, statement normalization, and rule derivation
Software detail

Existing parser, exact library not fixed here

The spec requires real parsing and deterministic bytes, but does not name the parser crate in the prose.

  • HTMLmust preserve sections, paragraphs, lists, tables, cells, headers, and offsets
  • ckc.lexproject lexicon maps surface forms, action verbs, modality phrases, and intervals
  • V5public-source adapters are registered later for HTML, XML, PDF, tables, and MEDIS terms
V3 model routes

If a model is used, it is measured separately

V3 uses a recorded local llama.cpp-family runtime under explicit experiment flags.

  • inputprompt template plus source text and route-specific schema
  • outputgrammar-constrained JSON or DSL, not trusted until admission checks pass
  • replayfixed seeds, recorded bytes, model identity, quantization, and prompt hashes in manifests
In this concept file, the span-picking mechanics figure represents the deterministic V1-V2 path, not a model route. HTML parser -> rule segmenter -> ckc.lex normalizer -> grounded records
