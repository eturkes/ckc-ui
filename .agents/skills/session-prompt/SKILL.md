# Session Prompt

Treat the invoking user message as a command with this shape:

```text
$session-prompt [TASK]
```

Task selection:
1. If the invoking message contains non-whitespace text after `$session-prompt`, use that text as the requested task.
2. If the invoking message contains no task text after `$session-prompt`, load `.agent/session-plan.md` and select the first queue item whose `status` is `pending`.
3. If `.agent/session-plan.md` is missing, empty, or has no parseable queue, ask the user for the missing task or plan before changing files.
4. If every queue item in `.agent/session-plan.md` is `done`, tell the user: `The CKC realism session plan is complete.` Do not change files.
5. For a selected plan item, treat the item title, intent, deliverables, and gate as the requested task. Complete exactly that item; avoid pulling in later queue items.

Work in `/run/host/home/eturkes/Projects/scratch/ckc-ui`.

Load order:
1. `AGENTS.md`
2. `.agent/session-plan.md` when using no-argument plan mode
3. `SPEC.md` sections needed for the requested unit
4. `.agent/memory.md` if it exists

Standing project intent: CKC is a headless clinical knowledge compiler. UI work must present research evidence, traceability, replay, artifacts, metrics, ledgers, and gates. It must avoid clinical decision-support claims unless explicit gate evidence exists.

Current seed artifact: root `index.html` is generated by `tools/build-run.mjs` from the ignored `runs/m2-one-shot/` evidence bundle. Treat it as a one-shot fixture-scale M1-M2 research harness view, not the normative compiler architecture.

Plan-mode closeout:
1. Run the selected item's gate.
2. If the gate passes and the item is complete, update `.agent/session-plan.md` by changing only that item's `status: pending` to `status: done`.
3. If the gate does not pass, leave the item `pending`, report the blocker, and do not start the next item.
4. Update `.agent/memory.md` only for lessons that future sessions need beyond Git history and the plan.

Default closeout:
1. Verify changed artifacts with local tools.
2. Keep `.gitignore` aligned with generated outputs.
3. Commit one scoped change before final response when work is complete.
